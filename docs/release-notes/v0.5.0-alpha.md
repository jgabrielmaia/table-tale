# Table Tale v0.5.0-alpha

> **Alpha.** Table Tale is still in alpha: features, data and URLs may change between versions.

Newcomers now choose their own community, and communities get a cover photo.

## What's new

- **Pick your community.** After the Fate Draw, new players choose which community to join instead of being added to "Table Tale" automatically. Players with no community see a prompt to find one. People who were already members stay where they are.
- **Community cover photos.** Owners and admins add, replace or remove a cover photo from the community's Manage tab (PNG, JPEG or WebP, up to 2 MB). It shows as a banner on the community page and on its card in the communities list.

## Changes you'll notice

- **BoardGameGeek import is switched off for now.** Search and import are hidden while we wait for BoardGameGeek to approve our API access; `/games/import` sends you to the Games page. The "Import from BoardGameGeek" button is also gone from the Games page header.

## Fixes

- Signed-out visitors can open the communities pages again: member counts no longer need a signed-in user.

## Behind a feature flag

- **BoardGameGeek integration** (`VITE_FEATURE_BGG`, off by default). When it's turned on, search results are cached for 7 days, requests time out instead of hanging, and importing a game that's already in the catalogue keeps the data we have and only fills empty fields from BGG. Turning it on needs the BGG API token, migration `20261112000007_bgg_search_cache.sql` and the `bgg` function deployed; see `docs/bgg-integration.md`.

## For developers

- Migrations: `20261112000003_community_member_count.sql`, `20261112000004_no_default_community_join.sql` and `20261112000006_community_cover.sql` are applied in production. `20261112000007_bgg_search_cache.sql` is not, on purpose (see above).
