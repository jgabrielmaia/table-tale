# Table Tale v0.3.0-alpha

Table Tale becomes a multi-community platform, and the library now speaks BoardGameGeek.

## What's new

- **Communities.** Create and join as many communities as you like. Each one has its own location (city, district, country), its own members and its own game library. Discover communities by name, city or district, and open any card with a single click or tap.
- **Members and roles.** Owner, admin, moderator and member, with membership requests for private communities. Owners can transfer ownership, and the last owner cannot leave by accident.
- **Faction balance.** Every community page shows how many Arcanists and Elementals live there, as a purple and cyan neon bar. Member photos are larger, and members appear as cards.
- **Personal and community libraries stay separate.** Your own collection is never affected by joining or leaving a community.
- **Go to library.** A shortcut from any community page to the library.
- **BoardGameGeek.** Search BoardGameGeek, preview a game and import it into the catalogue, then add it to your collection or to a community library you manage. Library filters now use BGG categories and mechanics instead of our own genre and complexity, and cards show BGG data.
- **City search.** When creating or editing a community, pick a city and its country and coordinates fill in. District stays manual, and everything still works by hand.

## Changes you'll notice

- The community page opens on **Members**; the Overview tab is gone (the location is in the header).
- Game filters use BGG categories and mechanics. Games that haven't been imported from BGG keep their old genre until they are.
- Form fields in the community editor were unstyled and are now visible.

## Needs setup before it works

- **BGG search and import** needs a BoardGameGeek API token stored as the Supabase secret `BGG_API_TOKEN`, and the `bgg` function deployed. It has not been tested against the live BoardGameGeek API yet.
- **City search** needs the secret `API_NINJAS_KEY` and the `city-search` function deployed. On the free API Ninjas plan it returns one city per search.

## For developers

- **Database** (already applied to production): community tables with row-level security, a read-only `game_ownerships` compatibility view over `user_games`, and additive BGG columns on `games`. Each migration has a matching rollback in `supabase/rollbacks/`.
- **CI** now runs a `migrations` job: it migrates a throwaway Postgres with seed data, rolls back, and migrates again.
- **Deliberately not shipped yet:** dropping the old `genre` and `complexity` columns (`supabase/contract/`), and running `supabase db push` and function deploys from the production pipeline. Both need follow-up work first.
